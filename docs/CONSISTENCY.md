# 一致性边界与崩溃恢复

本文描述管线在**乱序/迟到/重复/更正**、**增量与重算并存**、**进程失败**三类情况下
对外可见的一致性边界。

## 1. 持久化原语

所有状态落在 `<dataDir>` 下，三类文件，各自具备原子语义：

- `log/000000.seg ...`：长度前缀 JSON 帧的**仅追加**事件日志。一次
  `ingest` 是一次 append + `fsync` 的原子持久化边界；seq 无空隙、单调递增。
  崩溃产生的写坏尾帧在打开时按记录边界截断；零字节 segment 不进入 seq 链。
- `snapshots/<metric>/v<n>/snap-<seq>.ndjson`：**不可变**快照（NDJSON：首行
  header，其后每用户一行）。
- `snapshots/<metric>/v<n>/current.ptr`：指向当前快照的检查点指针。
- `recompute/<metric>/v<n>.marker`：**仅在重算未完成时存在**。

### 快照两阶段提交

1. 先把快照写入临时文件、fsync、原子 rename（此时尚无指针引用它）；
2. 再以临时文件 + 原子 rename 发布 `current.ptr`。

因此“快照文件”与“指针”严格区分：**有指针=已提交，无指针=垃圾**。恢复时临时快照
一律忽略。查询只读已提交快照文件，永不读正在更新的内存态。

## 2. 查询能看到什么

- 任意时刻，对单个指标，查询只能看到**一个已提交的自洽整体**（某个 commitSeq
  对应的完整快照），不会出现新旧混合。
- 增量排水按批提交：每批事件要么完整反映到新快照，要么完全不反映；失败时状态不变，
  下轮重放同一 seq 区间，不重复计入也不跳过。
- 查询与聚合完全解耦：查询顺序扫描不可变快照文件，不触碰聚合内存态，查询取消/超时
  不会影响正在进行的聚合。

## 3. 增量结果 == 全量重算

每个聚合器保存的是每用户的原始相关事件（按全序排序）。合并是幂等的：

- 未见 `(seq, eventId)` → 插入；
- 同 `eventId` 且 `revision` 更高 → 删除旧事实再插入新事实（更正，可跨用户/事件名）；
- 同 `eventId` 且 `revision` 相等/更低 → 忽略。

因此聚合结果是日志的**确定性纯函数**。后台重算把整份日志重放进独立状态，
在与增量状态相同的 seq 上做 NDJSON 行体 SHA-256 比对（逐行相等）才允许切换。

## 4. 重算期间不丢事件、结果可解释

`POST /api/admin/recompute/{metric}`：

1. 在该指标的提交锁内暂停其后台 worker（**不阻塞**摄入与其他指标，已持久化的新
   事件安全等待）；写入 `.marker`（BUILDING）。
2. 从日志头重放构建独立状态；构建期间摄入继续，live 状态继续对外提供旧快照。
3. 循环追平到日志最新 tip（若构建期间又有新事件则继续追），做 parity 校验
   （COMPARING）。
4. 校验通过 → 发布重建快照、原子切换指针、删除 marker；校验失败 → 抛错、保留旧指针。

重算前后对外结果都能对齐到某个 commitSeq，且都可在响应/状态中解释。

## 5. 崩溃恢复

进程重启时：

- **事件日志**：扫描校验 seq 连续，重建去重/版本索引，截掉坏尾帧；`latestSeq`
  是最后一个完整批次的 seq。
- **检查点**：每个 (指标,版本) 从 `current.ptr` 恢复到最后提交位置，随后从
  `commitSeq+1` 继续。
- **未完成重算**：存在 `.marker` 但没有对应指针的重建属于“未完成任务”，启动时
  被显式登记为 aborted 并清理 marker；旧检查点保持权威。**已提交结果与未完成
  任务严格可区分。**

## 6. 并发与资源隔离

- 每个 (指标,版本) 独立状态、独立 worker 调度，固定有界线程池
  `pipeline.worker-threads`。
- 单个指标变慢只会占用一个工作线程，其他指标继续推进；指标可被暂停/恢复
  （重算时）。
- 每个指标在内存中保留的事件数受 `pipeline.max-events-per-metric` 上界约束，
  超限时该指标暂停追赶并通过 lag 暴露背压，不会无界增长或覆盖结果。
- 维度分组数受每指标 `maxDimensionGroups` 约束（折叠进 `__OTHER__`）。
- 去重/更正索引随唯一 eventId 线性增长，并在启动时由日志重建；这是为保证“重复
  不计数、更正可回放”而显式保留的有界含义（容量规划见 OPERATIONS.md）。

## 7. 查询成本量级

- 快照为 NDJSON 顺序文件，游标为行序号，分页恢复不反序列化更早页。
- 用户明细页：一次顺序扫描，`O(当页扫描行数)` 时间、`O(pageSize)` 内存。
- 分组报表页：至多两次顺序扫描 + `O(N log K)` 堆选择（K=分组上界），
  峰值堆内存 `O(pageSize + maxDimensionGroups)`，与总用户数无关。
- 每次查询有 `pipeline.query-timeout-millis` 截止时间；超时或取消在行粒度检查点
  抛出，**不返回半页**，也不影响聚合。
